### haiku:medium

Notes, section "Key Concepts":

> **Comparable items.** The lecture models items as *comparable items*: black boxes that support only comparisons between pairs. The allowed comparisons are $<$, $\le$, $>$, $\ge$, $=$, and $\neq$. Each comparison returns a binary result, True or False. The algorithm cannot look inside an item, hash it, or use its bits.
>
> **Goal of the model.** Store a set of $n$ comparable items and support a `find(k)` operation. Since the algorithm can only compare, its running time is bounded below by the number of comparisons it performs. So the useful thing to count is comparisons.
>
> **Decision tree.** Any algorithm can be drawn as a decision tree of the operations it performs. For a comparison algorithm:
> - An **internal node** is a binary comparison, with one branch for True and one for False.
> - A **leaf** is termination, and it gives the algorithm's **output**.
> - A **root-to-leaf path** is one execution of the algorithm on some input.
>
> **Leaves and outputs.** Every possible output needs at least one leaf. A search over $n$ items can return any of $n$ found positions or report that the key is absent, so it needs at least $n+1$ distinct outputs. That means at least $n+1$ leaves.
>
> **The chain of inequalities.** The lecture states:
>
> $$\text{running time} \;\ge\; \#\text{comparisons} \;\ge\; \text{max length of any root-to-leaf path} \;\ge\; \text{height of tree}$$
>

Quiz, multiple_choice:

> In the comparison model, a search over a set of $n$ comparable items must produce a decision tree with at least how many leaves?
>   A. $2n$
>   B. $\log n$
>   C. $n-1$
>   D. $n+1$
> Key: D
> Explanation: ## Why $n+1$ leaves

- Each algorithm output needs at least one leaf.
- A search has $n$ possible positions for the key plus the case where it is absent, so it needs at least $n+1$ leaves.
- Counting leaves is the first step in the lower-bound argument.

Quiz, short_answer:

> Explain briefly why the decision tree argument shows that any worst-case comparison search needs $\Omega(\log n)$ comparisons.
> Sample answer: A comparison search must have at least $n+1$ leaves, and each root-to-leaf path is one execution whose length is at most the number of comparisons. A binary tree of height $h$ has at most $2^h$ leaves, so $2^h \geq n+1$ gives $h \geq \lceil \lg(n+1) \rceil - 1 = \Omega(\log n)$.
> Explanation: ## Answer outline

The argument chains three facts: leaves, path length, and the leaf bound for a binary tree. Together they give the worst-case lower bound on comparisons.
